## Status

README and banner usage guidance is complete for the current first-batch assets.

## Usage Rules

- Keep the header image at the top of the README before long prose.
- Do not crop the Redy mascot, product mark, or project-specific symbol.
- Avoid placing additional text over the existing banner PNGs.
- Use product badges below the banner only when the README needs quick project switching.
- Keep WeMail, WeGit, and WeOpen headers as a visual family: same spacing, same warm background behavior, and only local project accents.

## Replacement Rules

- Replace a README header only when the whole three-project set is updated together.
- If one project needs a variant, create the matching variants for the other two projects before marking the set final.
- For social previews, start from the corresponding README header and crop conservatively from the edges only.
