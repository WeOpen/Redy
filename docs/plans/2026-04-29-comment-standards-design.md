# 中文注释规范与覆盖设计

## 背景

当前项目注释较少，且部分注释使用英文。随着首页完成内容层、布局层、区块层拆分，文件数量增多，需要通过统一的中文注释规范帮助后续维护者快速理解文件职责、组件边界、关键方法和非显而易见的行级约束。

## 目标

本次采用“受控高覆盖”方案：在主要源码、测试和脚本中增加中文注释，同时避免给二进制资产、生成文件、锁文件和自解释配置制造无效噪音。

## 范围

纳入扫描与注释的文件：

- `app/**/*.ts`
- `app/**/*.tsx`
- `tests/**/*.ts`
- `tests/**/*.tsx`
- `scripts/**/*.ts`
- `next.config.ts`
- `docs/project-standards.md`

排除文件：

- `node_modules/**`
- `.next/**`
- `public/**`
- `brand/**` 中的图片、SVG 等资产
- `next-env.d.ts`
- `package-lock.json`
- JSON 文件，除非未来改用支持注释的配置格式

## 注释策略

### 文件注释

主要源码文件顶部增加中文文件职责注释，说明该文件在分层架构中的位置和维护边界。

### 方法注释

导出组件、导出函数、关键 helper 使用中文 JSDoc，重点说明用途、输入输出约束和维护注意事项。

### 行注释

行注释只放在关键逻辑附近，例如：

- 滚动激活阈值
- 动画降级逻辑
- 测试读取 PNG 元数据的原因
- 构建或配置中的非默认行为
- 结构回归测试的意图

## 风险控制

- 不改业务文案、链接、DOM 结构或 CSS class。
- 不为每个 JSX 标签添加机械注释。
- 不在 JSON、图片、SVG 或生成文件中插入注释。
- 注释统一使用中文，命令、标识符、错误信息保持原文。

## 验证

完成后运行：

```bash
npx vitest run tests/home-page.test.tsx
npm run build
```

如只修改注释与规范，浏览器预览不是必须；若触碰 JSX 结构，则重新做预览验证。
